## Why accuracy alone is misleading

Most patients need no transfusion of a given component, so a model that never recommends one is already "accurate": PRBC 0.806, Platelets 0.951, FFP 0.934, Any 0.718. Every method above sits within a few points of that, which says nothing about the patients who do need blood. Sensitivity, F1, AUROC and the share of the ceiling are the numbers to read.

## Clinical operating point (sensitivity ≥ 0.90)

Missing a needed transfusion is worse than an extra crossmatch, so a clinical deployment would not use the default 0.5 cut-off. Inside each outer fold the threshold is chosen on the training fold only (XGBoost: out-of-fold predictions from a 5-fold inner CV; ceiling: the label probabilities) as the highest one that keeps training sensitivity ≥ 0.90; the test fold is then scored at that threshold. PPV is the share of flagged patients who truly need the component: what reaching 90% sensitivity costs in extra crossmatches. The ceiling row shows how much of that cost is in the data itself.

Read the rows with a large noise share with care: PRBC 4%, Platelets 18%, FFP 5% of positives exist only through the label process's 1% record noise (clinical probability ~0, indistinguishable from patients who don't need blood). Reaching 90% sensitivity means reaching into that noise, so specificity drops for every method, the ceiling included, the more so the larger that share and the rarer the component. On real data this cost would depend on how noisy real transfusion records are.

Patients whose surgical context changes the guideline decision (the context-aware rule says transfuse, the static rule doesn't): PRBC 179, Platelets 45, FFP 0. This is where a model that sees surgery type can beat the static rule; FFP has no context adjustment, so there it can only tie.

Rules output yes/no, so AUROC and Brier are reported only for probabilistic methods. The ceiling is not a method: it's the probability the label generator itself used, so it bounds what any model can achieve on this data.
